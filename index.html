How it works

Three layers, no cloud.

The phone owns the model and the server. A gateway gives you one URL and one key for however many phones you run. The agent is whatever you already use.

01 · PHONE

The inference node

llama.cpp runs as a foreground service and listens only on loopback. The app proxies /v1 to it behind an API key. That proxy is the only thing on the LAN.

02 · GATEWAY

One endpoint, many phones

LiteLLM holds the registry: an alias per phone, retries and timeouts in one place. Parallelism is the number of phones — two phones run two tasks at once, each at one phone's pace.

03 · AGENT

Unmodified clients

Anything that speaks the OpenAI API can call it — an agent runner, a script, a chat client. Tool calls come back as structured tool_calls.

Measured

Burst is not sustainable. We report both.

A phone that serves an agent runs for hours. Fifteen minutes of continuous generation, 192 tokens at a time, with battery temperature sampled between requests: 6.31 tok/s median, a floor of 6.09, 35 °C at the end, and no throttle event. Burst is what a single short request gets; sustained is what you plan capacity with.

Thermal pause that drains

At the configured temperature the node stops accepting work, finishes what is in flight, then stops the engine. An agent gets a clean boundary, not a dead socket.

Battery policy

An unplugged phone below the threshold pauses serving and resumes on the charger or at the resume level. An unattended node is not run flat.

Verified models

Size and SHA-256 are checked before a model is used, and the volume is checked before a download starts. A truncated file is kept for resume; a wrong file is deleted.

Run it

One phone, one model, one endpoint.

The app targets arm64 Android 12 and newer. 8 GB of RAM runs the 2B tier; larger tiers are offered with the cost stated. Models are 1.3–2.9 GB and are downloaded at your request.

Get the app.

Builds are published on GitHub Releases; F-Droid inclusion is in progress. Source builds with one command from BUILDING.md.

Download a model in the app.

The picker shows measured rates, licence and the RAM tier. Over-tier models ask before they download.

Start serving and copy the endpoint.

Loopback is the default. Turning on LAN access requires an API key; the app refuses an open bind.

Point a client at it.

Any OpenAI-compatible client works. Two phones behind LiteLLM give you two workers.

# from the phone over adb, or from the LAN when enabled
curl http://<phone>:8080/v1/chat/completions \
  -H "Authorization: Bearer $PHONON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3.5-2b",
       "messages":[{"role":"user","content":"hello"}],
       "max_tokens":64}'
Limits

What it does not do.

Written down here so nobody discovers it in production.

  • One model per phone at a time, and one request in flight per phone; the second waits.
  • Pixel 7 is the only device with published measurements. Other phones are invited as pull requests carrying their own numbers.
  • Kiosk mode needs Device Owner, which a phone with accounts configured cannot grant. The app says so instead of pretending.
  • The app cannot control charging. Charge limiting is a platform or ROM feature; the app reads state and pauses.
  • No TLS on the LAN. The API key protects the endpoint; the traffic is plain HTTP by design.
  • No telemetry, and no phone-home. There is also no crash reporting, so issues are reported by hand.
